# 0005: Use GPUI for the GUI

- Status: Accepted, with a Phase 5 open item
- Date: 2026-11-11

## Context

The project aim is a native application in Rust with no web view. GPUI is the
GUI toolkit of the Zed editor. The facts about GPUI are in
[../kb/gpui.md](../kb/gpui.md). The important ones are:

- The `gpui` crate on crates.io is old. Current applications use a snapshot
  crate from a third party, or a Git revision of Zed.
- The API changes between snapshots.
- GPUI has no API for a menu bar item.

## Decision

The GUI application uses GPUI.

### Phase 2: dependency and widgets

Use the crates.io snapshot, through `gpui-kit = "=0.9.1"` with its default
features. This version selects `gpui-pre = 0.3.12`. Use the kit's GPUI
re-exports and its `gpui-component` widget layer. Do not use a Zed Git
dependency. Commit the application's `Cargo.lock` when the GUI crate is made.

The [test results](../kb/gpui.md#phase-2-api-test) show that the snapshot
supports each necessary Phase 2 function on stable Rust. A Git dependency
would add source and version alignment work without solving a tested
blocker. The kit keeps the GPUI family and the widgets together. Exact pins
and the lock file make updates deliberate.

Use the widget library because text entry is more than a key handler. The
bare alternative makes OpenCraft own focus, selection, text shaping,
clipboard, and input-method code. The measured widget cost is small enough
in memory and idle processor use to keep this code outside OpenCraft. Use
plain GPUI elements for the device layout. A few colour samples and the
native file dialog do not need larger widgets.

This choice does not meet the startup target yet. Even the widget test
program takes too long to submit its first frame. Keep this as an explicit
risk, not a passed product check. Repeat the measurements after integration
in [issue 58](https://github.com/shantanugoel/OpenCraft/issues/58). Improve
startup before Phase 6, or examine this choice again.

Keep Ubuntu workspace build and clippy coverage when the GUI is added.
Install the native packages in the [CI notes](../kb/gpui.md#platform-functions-and-ci).
Also check the native window on macOS. This issue adds no GUI crate and
changes no CI job.

## Results

- The GUI is native. The small test has measured memory, processor use,
  startup, and build costs. See the [release measurements](../kb/gpui.md#release-measurements).
  They do not replace measurements of the integrated application.
- OpenCraft must pin an exact version of GPUI and must plan time for API
  changes.
- Keep the required dependency licence texts, notices, and icon
  attributions in the release. The [licence notes](../kb/gpui.md#licences-and-update-cost)
  include the transitive dependencies; not all use Apache-2.0.
- The engine does not depend on GPUI (rule 12). Thus a different toolkit can
  replace GPUI if it blocks the work.
- Look at this decision again at the end of Phase 2, with the measured
  footprint and the experience from that phase.
